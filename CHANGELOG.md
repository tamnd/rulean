# Changelog

All changes that a user can see are in this file. The format follows Keep a Changelog, and the versions follow Semantic Versioning. Before 1.0, a minor version closes a milestone of `docs/spec/14-milestones.md` and a patch version is a step inside a milestone.

## [Unreleased]

### Added

- `scripts/lean-build.sh` makes the `lean` binary with rulean as its kernel on Linux too (spec 09.6.2). The Linux release of Lean uses libc++ and has no headers of libc++, so the script compiles the shell with `clang++ -stdlib=libc++` and links the static libc++ of the release. The CI job `lean-build` now runs on macOS and on Linux, and on the two systems the smoke test gives the same output with the `lean` of the release, the new `lean` and the dual-kernel build.
- The dual-kernel build measures the heartbeats of the two kernels (spec 09.6.4). If the environment variable `RULEAN_DUAL_BEATS` gives a file name, each `addDecl` that the two kernels accept writes the count of rulean, the count of the C++ kernel and the name of the declaration to the file. The new function `Kernel::cpp_beats` of `rulean-ffi` finds the count of the C++ kernel with a binary search on the limit. The search sets the heartbeats of the thread to 0 before each try, so use the variable only to measure. On 322 tests of `tests/elab`, rulean counted 66% of the heartbeats of the C++ kernel for 12339 declarations, and no declaration had a count of rulean above the C++ count.

### Fixed

- The in-process kernel uses the bound of `LEAN_NAT_MAX_SIZE` for `Nat` literals, as the C++ kernel does (spec 09.6.4). Before, rulean always used the default bound of 128 MiB, so with a smaller value it accepted a literal that the C++ kernel refused. The faults of the bound now give the messages of the C++ kernel. The checker has the new field `nat_max`, and `rulean-ffi` has the new function `kernel::nat_max_size`, which reads the value as `strtoull` does. The test `tests/elab/nat_size_limit.lean` of the Lean suite gave a different result with the dual-kernel build, and now it gives the same output as the C++ kernel.
- Engine R keys the caches of `infer_type`, `whnf_core` and `whnf` with terms that are equal up to binder names and binder info, as the C++ kernel does with `is_equal` (spec 05.5). Before, two terms that differed only in binder names had different keys, so engine R missed cache hits of the C++ kernel. The first calibration with `RULEAN_DUAL_BEATS` found 29 declarations where rulean counted more heartbeats than the C++ kernel, for example `Impl.size_balanceLErase` with 5346 heartbeats of rulean and 4675 of the C++ kernel. Such a declaration could time out with rulean and not with the C++ kernel, and that is not deviation D2. After the fix, the calibration found none.

## [0.0.18] - 2026-11-25

### Changed

- The mirrors of a pool share the names of the constants that made a check run again after a missed lookup (spec 09.6.3). Before, each new mirror missed the same constants, and its check ran again for each one. Now the walk of a mirror also starts from these names. On `tests/elab/vcgenSepLogic.lean`, 2 runs had 110 and 111 checks that ran again and a check of 769 ms and 733 ms. The build without this change had 203 and 209 checks that ran again and a check of 1197 ms and 1258 ms.
- The timing line of `RULEAN_FFI_TIMING` gives the time of the checks that ran again, and the count of the checks that ran again after a lookup of a name that the mirror did not have (spec 09.6.3). On `tests/elab/vcgenSepLogic.lean`, 703 ms of 1249 ms of the check were in these checks, and 156 of the 196 checks that ran again were after a missed lookup.
- A check with a cancel token runs on a worker thread that stays after the check (spec 09.6.3). Before, each check made a new thread with a stack of 1 GiB. Now a call makes a new thread only if all the worker threads have a check.
- The kernels of all the threads of the exported library share one pool of mirrors (spec 09.6.3). Before, each thread had its own mirror, so each thread converted the imported constants that its checks used. Now an `add_decl` call takes a free mirror from the pool, so the process has one mirror for each call that runs at the same time. The new type `MirrorPool` and the new function `Kernel::share_mirrors` of `rulean-ffi` give the pool to a kernel. A kernel with a pool marks each `ConstantInfo` object that a mirror keeps as shared between threads, with the new function `Runtime::mark_mt`. On the smoke test of the CI job `lean-build`, 3 runs converted between 4550 and 4998 constants, and the build without the pool converted between 7578 and 8250. The mirror took 76 ms to 88 ms, and before it took 133 ms to 151 ms.

### Fixed

- The check of a nested inductive type does not stop the process if the mirror does not have a constructor or a type of the block of the nested type. Before, the lazy mirror of 0.0.17 could leave out these constants, and the thread of the check stopped with a panic at `Env::at`. The check now gives the fault `UnknownConst`, and `add_decl` loads the constant and runs the check again. 7 tests of the Lean suite stopped with this panic, for example `tests/elab/structuralMutual.lean`.

## [0.0.17] - 2026-11-25

### Changed

- The mirror of `rulean-ffi` converts only the constants near a declaration (spec 09.6.3). Before, each `addDecl` walked all the constants that the check could use, and a thread converted about 36000 imported constants for the smoke test of `lean-build`. Now the walk goes at most 3 steps from the constants of the declaration. `Env::find` of `rulean-core` records the names of the lookups of the check, and after the check the mirror compares each name with the Lean environment. If a lookup does not agree, the mirror removes the new constants of the check, walks from the names of these lookups, and checks the declaration again. A lookup that finds no constant for a name that the mirror does not know stops the check with the new fault `ErrorKind::Missed`, and the first pass has a limit of 10^6 heartbeats that grows 10 times after each pass that stops at it. In 3 runs of the smoke test on a machine with other work, the mirror converted between 5806 and 7826 constants and used between 150 ms and 286 ms, and the check used between 111 ms and 248 ms. The build before this change used between 7489 ms and 12555 ms for the mirror at the same time.
- `Env::find` and `Env::contains` of `rulean-core` take `&mut self`, because they record the name of the lookup when the record is on. The new function `Env::peek` gives the slot with no record. The new functions `Env::record_start`, `Env::record_stop`, `Env::take_record`, `Env::missed`, `Env::known_reset` and `Env::mark_known` control the record. The checker stops with `ErrorKind::Missed` at the next heartbeat if `Env::missed` is true.
- The counts and the conversion time of `rulean_ffi::kernel::timing` are for `add_decl` only. Before, they also had the walks of the term functions.

### Fixed

- `Env::truncate` of `rulean-core` removes the record of the quotient constants if it removes them.
- `rulean-ffi` gives the texts of the C++ kernel for three more rejections. A use of an unsafe constant gives "invalid declaration, it uses unsafe declaration 'N'", and a use of a partial constant gives "invalid declaration, safe declaration must not contain partial declaration 'N'". A constructor with a return type that is not valid gives "invalid return type for 'C'", and a duplicate constructor name gives "duplicate constructor name 'C'". Before, rulean gave its own text for these rejections, and the tests `elab_fail/2125`, `elab_fail/partialIssue` and `elab_fail/sanitychecks` of the Lean suite gave a different output. For the fault `BadCtor`, `Fault::ty1` of `rulean-core` now has the return type of the constructor if the return type is not valid.

## [0.0.16] - 2026-11-25

### Added

- `Kernel::elab_add_decl` and `Kernel::elab_add_decl_without_checking` of `rulean-ffi` and the exported symbols `lean_elab_add_decl` and `lean_elab_add_decl_without_checking` (spec 09.6.2). The elaborator of Lean v4.36.0 adds each declaration with `lean_elab_add_decl`, which is C++ code that calls the C++ kernel directly. The rulean functions take the kernel environment of the `Lean.Environment`, check the declaration with rulean, and give the new kernel environment to `lean_elab_environment_update_base_after_kernel_add`, as the C++ functions do. The test `dual` gives three declarations to the C++ functions and to rulean and requires the same verdicts, exceptions and constants.
- The script `scripts/lean-build.sh` makes a `lean` binary of Lean v4.36.0 with rulean as its kernel, on macOS (spec 09.6.2). It renames the kernel symbols of `libleancpp.a` of the release with the suffix `_cpp`, and links the static libraries of the release with the static library of `rulean-ffi`. The CI job `lean-build` runs `tests/lean-build/smoke.lean` with the `lean` of the release and with the new `lean`, and requires the same output.
- The dual-kernel build of spec 11.3.1. `scripts/lean-build.sh --dual` makes a `lean` binary that calls the C++ kernel and rulean on each declaration and each term function, and stops if the results differ. The new feature `dual` of `rulean-ffi` enables this mode. `Kernel::compare_add` and `Kernel::compare_term` compare two results: the verdicts, the constructors of the exceptions, the result of `isDefEq`, and the constants of an inductive block. A timeout of the C++ kernel, and an interruption of either kernel, agrees with each result of the other kernel. The test `dual` checks that the functions find no difference for the test declarations and terms, and that they find a made difference. The CI job `lean-build` runs `tests/lean-build/smoke.lean` with the dual-kernel build.
- `Kernel::add_decl` of `rulean-ffi` records the kernel diagnostics of `set_option diagnostics true` (spec 09.6.4). The new fields `Checker::diag_on` and `Checker::diag` of `rulean-core` count the unfolds of each constant at the steps where the C++ kernel records them: the unfold of a definition or a theorem, and the step of a recursor or a quotient constant. If the diagnostics of the environment are enabled, rulean records the counts with `lean_kernel_record_unfold` and puts them into the new environment. The test `elab/ack` of the Lean suite now gives the counts of the C++ kernel, and the smoke test of the CI job `lean-build` compares the counts of a theorem.
- The script `scripts/lean-suite.sh` runs the tests of `tests/elab` and `tests/elab_fail` of the Lean source with the `lean` of the release and with the `lean` of `scripts/lean-build.sh`, and compares the output and the exit code of each test (spec 09.6.5).
- `rulean-ffi` measures the time of each part of `add_decl` (spec 09.6.3). `rulean_ffi::kernel::timing` gives the sums for all the threads, and if the environment variable `RULEAN_FFI_TIMING` has a path, the process adds the line of `Timing::report` to that file at exit.

### Changed

- The mirror of `rulean-ffi` replaces a constant that the Lean environment has with a different object, and removes a constant that the Lean environment does not have (spec 09.6.3). Before, each of these constants made a new mirror, which converted all the imported constants again. The new function `Env::remove` of `rulean-core` removes a constant. `MirrorStats` and `Timing` have the new counts `replaced` and `removed`, and `Timing` also has `rebuilds`. On the smoke test of the CI job `lean-build`, 3 runs made no new mirror after a stale constant. Two runs before this change made 16 and 18.
- The mirror of `rulean-ffi` converts the imported constants in less time (spec 09.6.3). The tables of the conversion and the sets of the walk use a multiplicative hash in place of SipHash, one walk uses one converter, and the lookup of a constant of the mirror uses the `Name` object of its `ConstantInfo`. On the smoke test of the CI job `lean-build`, the mirror used 8410 ms before and between 1576 ms and 3767 ms after, on a machine with other work.

### Fixed

- The local context of a kernel exception has only the free variables in scope at the fault, as in the C++ kernel (spec 09.6.4). Before, it had each free variable of the check, also the free variables of the binders that the check had left, of engine F, and of the nested steps of an inductive block. Lean then printed a free variable as `w✝⁷` in place of `w`. The new list `Checker::scope` of `rulean-core` has the free variables in scope. The tests `elab/issue_14576` and `elab/issue_14576_min` of the Lean suite now give the output of the C++ kernel.
- Primitive pinning accepts the axiom form of a target (spec 05.8). In a file with `module`, the elaborator adds `Nat.gcd`, `Nat.land`, `Nat.lor` and `Nat.xor` as axioms, because their bodies are not exposed. The C++ kernel reduces these constants by name, but rulean turned off the extension, and a proof such as `Nat.ne_of_beq_eq_false (Eq.refl false)` failed. The new table `pin_axiom_v4_35.in` has the digest of the axiom form of each target, and `scripts/pin-digests.py --axiom` makes it. The CI job checks the table.
- The term functions of `rulean-ffi` accept a local context with metavariables (spec 09.6.4). The conversion skips a local declaration whose type or value has a metavariable, and a term that uses the local gets the fault of the conversion. A level metavariable in a term becomes the reserved universe parameter `_rulean_lmvar.N`, and the result has the original level metavariable. The local context of an exception starts from the `LocalContext` of the call, so it has the skipped locals.
- `Kernel::add_decl` of `rulean-ffi` gives `declHasMVars` and `declHasFVars` for a declaration with a metavariable or a free variable, in place of `other` (spec 09.6.4). The exception has the name of the constant and the term of the first part with one, in the order of the checks of the C++ kernel. The new `conv::decl_vars` finds this part. The test `dual` gives 7 such declarations to the two kernels and requires the same exception, name and term. The test `impossibleTactic` of the Lean suite now gives the output of the C++ kernel.
- The binder names of a generated recursor follow `Name.appendAfter` of Lean v4.36.0 (spec 06.6). The suffix of a hygienic name goes before its macro scopes, and the suffix of a name with a number as its last part is a new string part. Before, rulean added the suffix at the end of the name, so the type of a recursor of an inductive type with hygienic binders was not the same as in the C++ kernel. The new tests `names` of `rulean-core` have the results of `Name.appendAfter` and `Name.appendIndexAfter` of Lean for 15 names. The test `inductive_pred` of the Lean suite now gives the output of the C++ kernel.
- The term functions of `rulean-ffi` accept a term with a free variable that is not in the local context (spec 09.6.4). The conversion gives the variable a far free variable of the store, which has a level of `rulean_core::expr::FAR_FVAR` or more. The checker gives "unknown free variable" only when it infers the type of the variable, as the C++ kernel does, and the encoder writes the original `FVarId` back. The test `dual` gives 7 terms with such a variable to the two kernels, and the test `isDefEqProjIssue` of the Lean suite now gives the output of the C++ kernel.
- `Kernel::add_decl` of `rulean-ffi` gives the messages of the C++ kernel for the checks of a mutual block, the reserved prefix `_nested`, an occurrence of an inductive type that is not uniform, and a constructor with too few parameters (spec 09.6.4). Before, the message of `other` was the message of rulean. If an inductive block declares a name two times, for example a constructor `X.rec` of the type `X`, `alreadyDeclared` now has the name that the C++ kernel gives. The tests `kernelMutualDupName`, `mutualLevelParams`, `kernelNestedAuxName`, `issue_14576_nonuniform` and `recconstructorcrash` of the Lean suite now give the output of the C++ kernel.
- The term functions of `rulean-ffi` accept a projection index of 2^31 or more (spec 09.6.4). Before, the conversion stopped at an index of 2^32 or more with "a count or an index does not fit in 32 bits". Now the conversion gives such an index the far index `conv::FAR_PROJ + k`, and the encoder writes the original index back. The checker gives `invalidProj` for a far index, and `whnf` keeps the term, as the C++ kernel does. The test `dual` gives 5 queries with such an index to the two kernels, and the test `kernelProjIdx` of the Lean suite now gives the output of the C++ kernel.
- The `typeExpected` exception of `Checker::is_prop` of `rulean-core` has the type of the term, as in the C++ kernel (spec 09.6.4). `is_prop` gives the fault when the type of a term is not a sort. The C++ kernel calls `ensure_sort` on the type and gives the type in the exception, but rulean gave the term. The new test `is_prop_gives_the_type_in_the_fault` of `rulean-core` checks the term of the fault, and the test `kernel_is_prop_issue` of the Lean suite now gives the output of the C++ kernel.
- `Kernel::add_decl` of `rulean-ffi` uses the recursion limit `max_rec_depth` of the call (spec 09.6.4). Before, rulean ignored the limit. The new field `Checker::max_rec_depth` of `rulean-core` is the limit, and 0 is no limit. The checker counts the depth of `infer_type_core`, `whnf_core` and `is_def_eq_core`, as `scope_rec_depth` of the C++ kernel does, and gives `ErrorKind::DeepRecursion` when the depth is above 16 times the limit. The new test `recursion_depth_limit_stops_the_check` of `rulean-core` checks the limit, and the test `kernelMaxRecDepth` of the Lean suite now gives the output of the C++ kernel.
- `scripts/lean-build.sh` makes `OUT/bin/cadical` a link to the `cadical` of the release, because `bv_decide` runs the SAT solver from the directory of `lean`.

## [0.0.15] - 2026-11-25

### Added

- The mirror of `Kernel::add_decl` of `rulean-ffi` stays between the calls of a thread (spec 09.6.3). Each constant of the mirror keeps a reference to its `ConstantInfo` object, and a call converts only the constants whose object is not in the mirror. If a constant that the check can use is not the same object in the Lean environment, the call makes a new mirror. The checker of the mirror has no session, so the heartbeats of a declaration do not depend on the earlier calls. `Kernel::mirror_stats` gives the counts of converted constants, reused constants and new mirrors. The test `dual` checks that a chain of declarations converts no constant again, that two environments with different constants of the same name get the verdicts of the C++ kernel, and that the heartbeats are the same with a new kernel and with the full mirror.
- `Kernel::add_decl` and the term functions of `rulean-ffi` give the `Kernel.Exception` constructors `declTypeMismatch`, `funExpected`, `typeExpected`, `letTypeMismatch`, `appTypeMismatch` and `invalidProj` with their fields, in place of `other` (spec 09.6.4). The local context of an exception is a `LocalContext` object with the free variables of the checker. After a rejection in in-process mode, `Checker::add_decl` of `rulean-core` copies the terms of the fault and the local context into the frozen tier of the store, so the caller can read them. `Fault` has the new fields `ty1` and `ty2` with the types of an `appTypeMismatch` or a `declTypeMismatch`. The new `Checker::local_count`, `Checker::local` and `Checker::dummy` give the local context. The test `dual` gives 10 declarations and 5 terms that the kernels reject, and requires the constructor of the C++ kernel for each one.

## [0.0.14] - 2026-11-25

### Added

- `Kernel::add_decl_without_checking` of `rulean-ffi` and the exported symbol `lean_add_decl_without_checking` (spec 09.6.2). They do what the C++ kernel of Lean v4.36.0 does when `check` is false. An axiom, a definition, a theorem and an opaque constant get no check. A mutual block must not be empty and must be unsafe or partial. An inductive block and the quotient get the full check, as in the C++ kernel. The test `dual` gives each declaration to the C++ function and to rulean and requires the same verdicts and the same declared constants. The CI job `ffi-runtime` checks that the static library exports the symbol.

- `Kernel::is_def_eq`, `Kernel::whnf` and `Kernel::check` of `rulean-ffi` and the exported symbols `lean_kernel_is_def_eq`, `lean_kernel_whnf` and `lean_kernel_check` (spec 09.6.2). They take a `Lean.Environment`, a `LocalContext` and terms, as the C++ functions of Lean v4.36.0 do. The new `Converter::local_context` reads the local declarations of a `LocalContext`, and `Converter::expr` converts a term with free variables of the context. `Encoder::with_fvars` writes a free variable of the store as `Expr.fvar` with its `FVarId`. The test `dual` gives 15 queries in a local context with a `let` declaration to the C++ functions and to rulean, and requires the same results. The CI job `ffi-runtime` checks that the static library exports the three symbols.
- `Checker::mk_local` of `rulean-core` is now public.

- The heartbeat limit of the checker (spec 09.6.4). `Checker::max_heartbeat` of `rulean-core` is the limit, and 0 is no limit. The checker counts one heartbeat for each call of `infer_type_core`, `whnf_core` and `is_def_eq_core`, as `check_system` of the C++ kernel does, and the count starts at 0 for each declaration. Above the limit, the check stops with the new `ErrorKind::Heartbeat`, which is a resource failure. `Kernel::add_decl` of `rulean-ffi` gives the limit `max_heartbeat` to the checker, and a timeout gives `Kernel.Exception.deterministicTimeout`. The test `dual` finds the smallest limit with which each kernel accepts each declaration, and requires that the count of rulean is not above the count of the C++ kernel.

- The cancel token of `Kernel::add_decl` of `rulean-ffi` (spec 09.6.4). With a token, the check runs on a new thread, and the calling thread reads the flag of the token each millisecond. A set token gives `Kernel.Exception.interrupted` at once, and the check continues on its thread until it ends, and its result is discarded. Without a token, the check runs on the calling thread as before. The test `dual` gives each accepted declaration to the C++ kernel and to rulean with a set token and with a token that is not set.

### Fixed

- For an axiom, a definition, a theorem, an opaque constant and a mutual block, `Kernel::add_decl` now adds the `*Val` object of the declaration, as the C++ kernel does. Before, it wrote the constant again from the store, and the conversion into the store removes `mdata`, so the terms in the Lean environment had no `mdata`. The elaborator reads `mdata`, for example in the values of definitions.

## [0.0.13] - 2026-11-24

### Added

- The new module `rt` of `rulean-ffi` finds the functions of the Lean runtime when the program runs (spec 09.6.3). `Runtime::open` loads `libleanshared` of Lean v4.36.0 with `dlopen` and initializes the Lean modules one time in the process, and `Runtime::process` finds the functions in a Lean process. `dlopen` and `dlsym` are in the platform library, so the crate has no link-time dependency on Lean. `LeanMake` implements `Make` with the constructors that Lean exports, so Lean computes the cached data of each name, level and term. For other constructors it does what `lean_alloc_ctor` does, and the reference counts follow `lean_inc_ref` and `lean_dec_ref` of `lean.h`. The module is on Linux and macOS with 64-bit pointers.
- The CI job `ffi-runtime` runs the test `runtime` of `rulean-ffi` with the library of the Lean v4.36.0 release. The test writes each kind of term and constant with `LeanMake`, reads the objects back, gives terms to `Expr.dbgToString` and `Expr.equal` of Lean, checks the reference counts of shared terms, and frees a term of depth 100000. Without `RULEAN_LEAN_LIB`, the test uses the elan toolchain of v4.36.0 if it is there, and else it does nothing.
- `Encoder::declaration` of `rulean-ffi` writes a `Declaration` object for each kind of declaration (spec 09.6.3). An inductive block gives `inductDecl` with the types and their constructors in the order of `cidx`, and a quotient gives `quotDecl`.
- The dual-kernel test `dual` of `rulean-ffi` (spec 09.6.5). It gives each test declaration as one `Declaration` object to `lean_add_decl` of the C++ kernel of Lean v4.36.0 and to rulean, and requires the same verdict. The declarations are two inductive types, `Eq`, the quotient, definitions that need an iota step, an unsafe mutual block, and five declarations that both kernels must reject. Then the test reads 18 constants from the C++ environment and requires that they are the same as the constants of rulean. The CI job `ffi-runtime` runs it.
- The new module `kernel` of `rulean-ffi` has `Kernel::add_decl`, with the contract of `lean_add_decl` (spec 09.6.2). It checks a `Declaration` object against a Lean `Kernel.Environment` with rulean, and gives an `Except Kernel.Exception Kernel.Environment` object. It mirrors the transitive closure of the constants that the check can use with `lean_environment_find`, and adds the new constants with `lean_environment_add`. The kinds `unknownConstant`, `alreadyDeclared`, `thmTypeIsNotProp`, `excessiveMemory` and `deepRecursion` have the constructors of the C++ kernel, and the other kinds give `other` with a message. The mirror is made again for each call, and the heartbeat limit, the recursion limit and the cancel token have no effect yet. The test `dual` gives each declaration to `Kernel::add_decl` too, and compares the verdicts, the exception constructors and the constants of the result environments with the C++ kernel.

- The new feature `export` of `rulean-ffi` exports the symbol `lean_add_decl`, with the signature of the C++ kernel of Lean v4.36.0 (spec 09.6.2). The command `cargo rustc -p rulean-ffi --release --features export --crate-type staticlib` makes the static library that a build of Lean can link in place of the C++ kernel. Each thread gets its own `Kernel`, which finds the functions of the Lean runtime in the process. With the feature, the test `dual` gives each declaration to the symbol too and requires the result of `Kernel::add_decl`. The CI job `ffi-runtime` runs the test with the feature, makes the static library and checks that it exports `lean_add_decl`, and the job `clippy` checks the crate with the feature.

### Fixed

- The recursor that rulean makes for an inductive type now has the binder info of the C++ kernel. rulean does what `infer_implicit(rec_ty, true)` does in `inductive.cpp`, so the motive, the parameters and the indices are implicit in the usual case. Before, each binder had the default binder info. The four quotient constants now have the binder names and the binder info of `quot.cpp`. Before, the binders had no names and the default binder info. The checks compare these types up to α-equivalence, so no verdict changes, but in the in-process mode the elaborator reads the binder info (spec 06.6 and 09.6). The dual-kernel test found the two differences.

## [0.0.12] - 2026-11-24

### Added

- The CI job `proof-kernels` exports the proof package `RuleanProof` and its imports with lean4export, and requires that rulean, nanoda and con-leche accept the export (spec 10.9 and rule 5 of the release gate in 11.7). nanoda is built from the commit that the Lean Kernel Arena pins. con-leche is the package that `proof/` requires, and it runs in verified mode. The new script `scripts/proof-kernels.sh` does the export and the three checks.
- The release workflow builds each target on two runners. The second runner uses a checkout at a different path. The job `verify` compares the SHA-256 hashes of the two binaries, and the release is not published if they are different (spec 12.6). The compiler replaces the checkout path and the Cargo home with fixed names, and on Windows the linker writes no time stamp and no full PDB path. A pull request that changes the build runs the two builds and the comparison, but makes no release.
- The semantics profile `v4.37` for Lean v4.37.0-rc1 and the later 4.37 releases (spec 05.2). It has the rules of lean4#15103 (proof irrelevance before `whnf_core`), lean4#15371 (no `whnf` of a major premise that is a proof, and structure eta of the major premise when the recursor can eliminate into `Type`) and lean4#15373 (eta of a partial constructor application). ## [0.0.5] - 2026-11-22

### Added

- `rulean-io` is the island of contract K2 (spec 10.7). It opens the input read-only and reads it in blocks of 1 MiB. `rulean check`, `rulean pack` and `rulean explain` read the input through it. After the run, `rulean check` and `rulean pack` read the file again and compare the SHA-256 digests. If the file changed, `rulean check` gives exit code 4 and no verdict, and `rulean pack` writes no file. The second read costs 1.5 s and 29 G instructions on the 584 MB export of Std, about 7% of the check. Standard input and a pipe cannot be read again, so the check does not apply to them.
- `proof/RuleanProof/Contracts.lean` states contract K2 as `ReadsAs`. The field `K2` of `Interface` is still a free proposition.
- `rulean check --threads N` checks the declarations with the two-stage scheduler of spec 08.3. The add stage runs in input order on one thread. It adds each axiom, definition, theorem and opaque constant with a check of the name only, and it checks each inductive and quotient declaration fully. The check stage puts the other checks into 256 jobs of consecutive declarations with about the same cost, and runs them on N threads. Each check sees only the constants before its declaration. The verdict, the rejected declaration, the quarantine and the axioms are the same as with one thread on all 225 Arena tests, and `scripts/arena-threads.sh` compares them in the `arena` CI job. Each worker keeps its session from one job to the next. On Std with four threads, the check stage had 3.9 jobs running at a time on average, and the run took 462.7 G instructions, against 449.2 G with one thread. The wall time went from 133.5 s to 35.7 s, but the test machine had other load during these runs, so the wall times are not exact. Each worker has a copy of the store, so the peak memory goes from 880 MB to 3285 MB. The default is one thread, which is the sequential check.
- `rulean-pool` has `run_all`, which runs each job one time on a set of scoped threads and puts each result in the slot of its job (contract K1), and `largest_first`, the order of jobs with the largest cost first. The Verus proof of K1 is not done yet.

## [0.0.4] - 2026-11-22

### Added

- `rulean check` checks an export with engine R. It reads the export, selects the semantics profile from the `lean.version` field of the meta line or from `--profile`, and checks the declarations in input order. It stops at the first declaration that is not accepted. The exit code follows spec 09.3: 0 for accept, 1 for reject, 2 for decline, 3 for a resource limit and 4 for a malformed input. An export from a Lean version with no profile declines with `unsupported-version`.
- `rulean check --report FILE` writes the JSON report of spec 09.4, and `--format json` writes the report to standard output. The report has the SHA-256 of the input, the profile, the verdict, the counts, the deviations, the quarantine array of spec 05.10 and the pin mismatch array. The schema is in `docs/report.schema.json`.
- `rulean check --trust-primitives-by-name` keeps the literal extensions on when a pin digest is not equal to its reference.
- `rulean-core` has the semantics profiles of spec 05.2. This version has only the `v4.35` profile, for Lean v4.35.0, v4.36.0 and the v4.36.x releases. `rulean version` lists the profiles.
- `rulean-format` has `parse_export`, which gives the declarations and the `lean.version` and `format.version` fields of the meta line.
- `scripts/arena-run.sh` is the entry of rulean in the Lean Kernel Arena. It runs `rulean check --profile v4.35` and maps the exit codes of spec 09.3 to the three Arena codes. `docs/arena/rulean.yaml` is the draft of the Arena entry.
- `scripts/arena-check.sh` runs the Arena entry on every Arena test and compares each verdict with the expected verdict. `docs/arena/either-v4.35.tsv` pins the verdict of each "either" test for the `v4.35` profile to the verdict of the official kernel v4.35.0. The `arena` CI job runs the script. All 225 tests of the Arena tarball give the expected verdict.
- `scripts/arena-build.py` builds the exports of the Arena tests that are not in the Arena tarball, with lake and the `leanexport` binary of the Lean toolchain. It keeps only the exports with the hash of the results. The new `arena either` CI job builds the 30 "either" tests with the Lean v4.36.0 release and checks the verdicts. `scripts/arena-check.sh` reads the `either/` directory and does not run the 2 tests on which the official kernel timed out. The other 28 tests give the pinned verdict.
- `rulean-format` has `Stream`, a parse that takes the export one line at a time. `parse_export` uses it.
- `rulean-core` has `sha256::Hasher`, a SHA-256 digest that takes its input in parts.
- `rulean-core` has the value arena of engine F (spec 04.5), in the module `value`. It holds values, closures, environments, spines and unfolding slots in typed arrays with `u32` handles. Environments and spines are persistent lists, so a push copies nothing. `reset` clears the arena at the end of a declaration. Engine F does not use it yet.
- `rulean-core` has `eval`, `apply`, `force` and `quote` of engine F (spec 05.4.2 and 05.4.3), in the module `nbe`. `eval` does beta and zeta and makes a glued value for each definition. `force` gives the weak head normal form of a value: the `Nat` extension, delta, iota, the quotient rules and the projections. It unfolds a glued value once and keeps the result in its slot. K-like reduction and structure eta read the major premise back and use engine R. `quote` reads a glued value back in folded form. The checker does not use engine F yet.
- The checker error `ArenaFull` is a resource failure, with exit code 3.
- `rulean-core` has definitional equality of engine F on values (spec 05.4.4), in the module `conv`. It uses the quick checks, beta, delta, iota, the `Nat` extension, proof irrelevance, lazy delta on folded definitions, the same head with equal arguments and function eta. It keeps the pairs of values that are not equal for the current query, and does not compare them again. Proof irrelevance does not read a value back if the head of the value shows that the value is not a proof. Engine F answers a query first. An "equal" answer is final, except in the confirm set of spec 05.1, where engine R confirms it. A "not equal" answer, or a fault of engine F, makes engine R decide the query.
- The value arena of engine F has a limit of 2^22 nodes in each array, about 0.2 GiB (spec 04.9). At the limit, engine R decides each query of the rest of the declaration. On the Arena test `ite-taken-branch-bad`, engine F took more than 90 s and 3.2 GB before this limit, and now it takes the same time as engine R.
- `rulean check --engine F|R` selects the engine, and `--confirm default|all` selects the queries where engine R confirms engine F. In this version the default is `--engine R`, because engine F is new. The JSON report has the new `engine` object with the counts of engine F.
- `scripts/arena-confirm.sh` runs engine F with `--confirm all` on each Arena test and fails if engine R does not confirm an equality of engine F. The `arena` and `arena either` CI jobs run it.
- `rulean diff INPUT --against CMD` checks an export with rulean and with another checker, and compares the two verdicts (spec 11.3). It reads the exit codes of the other checker as the Arena does. It exits with 0 if the verdicts are the same and with 1 if they are different. It takes the check options, such as `--engine`. It does not yet compare the verdict of each declaration.
- `rulean explain INPUT DECL` checks an export up to the declaration DECL and prints the rule trace of DECL (spec 09.2). Each line is one rule that the checker applied: delta, iota, the quotient rules, the `Nat` extension, proof irrelevance, function eta, structure eta, the unit-like rule, the string literal rule, and the answers of engine F. The indent shows the depth of the checker, and the last lines give the count of each rule. The trace keeps at most 100000 events. It takes `--profile`, `--engine` and `--confirm`.
- The proof package has the reordering lemmas O1 to O5 of spec 05.7.3, in `Twin/Order.lean` and `Twin/Zeta.lean`. A twin of the conversion loop has the quick check, the head reduction without delta, lazy delta with heights, a cache of equal pairs and the congruence of applications. The main theorem, `convF_conv`, says that each answer of the order of engine F is also an answer of the official order with some fuel. `convF_agrees` says that if both orders give an answer, the answers are equal. `zeta_lazy` says that a lazy `let` gives the value of the official substitution for a closed value. The twin terms have no binders and no types, and the link to the Aeneas model of engine F is not done yet.
- `rulean check --axioms LIST` gives the axioms that a theorem can use (spec 09.2). LIST is `any`, `none`, or names and `std` with a comma between them, and `std` means `propext`, `Quot.sound` and `Classical.choice`. The default is `any`. If every declaration is accepted but a theorem uses an axiom outside the list, the verdict is `axiom-policy` with exit code 5. `rulean check --format text --axioms std` is the command for an external kernel of `lake comparator`, and lake adds the path of the export at the end (spec 09.5).
- `tests/lake` is a small Lean project, and `scripts/lake-comparator.sh` runs `lake comparator` on it with rulean as an external kernel. The script also requires exit code 5 from `--axioms std` on a theorem that uses `sorry`. The new `lake comparator` CI job runs the script with the `bwrap` sandbox of lake and the Lean v4.36.0 release.
- `rulean-core` has the module `axioms`. It computes the axioms of each constant as `#print axioms` does: an axiom gives itself, a definition or a theorem gives the axioms of the constants in its type and its value, and an inductive type also gives the axioms of its constructors. The members of an inductive group share their axioms. The JSON report has the new field `summary.axioms_used`, with the axioms that the accepted theorems use.
- The checker keeps a session: the results of `infer` in infer-only mode, `whnf_core`, `whnf`, the definitional equality successes and the unfoldings of constants with level arguments, on frozen terms without free variables, stay from one declaration to the next (spec 08.4). The entries of a declaration go into the session only if the declaration is accepted. A result in the scratch tier is first copied into the frozen tier, with at most 10% of the scratch nodes of the declaration. Each entry has the length of the environment as its stamp. The session has at most 128 MiB, with a CLOCK policy in buckets of 4 entries. The session is not used with `rulean explain` and with `--confirm all`. `rulean check --session off` turns it off. The JSON report has the new `session` object with its counts. On the Init export of the Arena (58547 declarations), engine R used 306.5 G instructions and now uses 266.3 G, and the parse is 72.5 G of this. On the std export, engine R used 494.0 G and now uses 437.1 G, and the peak memory went from 971 MB to 1108 MB.
- `rulean pack INPUT -o OUT.rlb` writes the binary format of spec 07.2 from an NDJSON export, and `rulean check` reads a `.rlb` file. It finds the format from the first 8 bytes of the input. The decoder is in `rulean-format`, in the module `rlb`. It reads the tables in one forward pass, checks each index, each pad and the CRC-32C of each section, and makes each node again with the constructors of the store. The encoder is in `rulean-pack`. The JSON report gives the format `rlb-1` for a binary input. On Init, the file has 85 MB and the NDJSON export has 348 MB, and the parse takes 9.8 G instructions and not 72.6 G. On Std, the file has 140 MB and not 584 MB, and the parse takes 17.0 G and not 121.3 G. A full check of Std from the `.rlb` file takes 334 G instructions and 49 s, and from the NDJSON export it takes 439 G instructions and 67 s. The decode takes about 115 instructions for each byte, so the target of 3 instructions for each byte in spec 07.2.3 is not met.

### Changed

- Engine F does not run on a query whose success is already in the success cache of the declaration or in the session. On the Init export, engine F with `--session off` used 1026.1 G instructions and now uses 977.6 G. With the session, it uses 950.6 G. Engine R is still much faster on this export, at 266.3 G, so engine R stays the default.
- Proof irrelevance in engine F does not read back a value whose head is a local of a type that is not a proposition, for example `f : α → α` with `α : Type`. On the Arena test `church-numerals`, engine F used 251.09 G instructions and now uses 0.05 G.
- Engine F keeps the result of the `Nat` extension in the unfolding slot of the glued value, so the next `force` of the value does not compute it again. On the Arena test `gf3-matrix-product`, engine F used 148.94 G instructions and now uses 109.55 G.
- Engine F keeps the pairs of values that it found equal for the current query, and does not compare them again (row O2 of spec 05.7.3). On the Arena test `repeated-subproblem`, engine F used 3.71 G instructions and now uses 0.02 G.
- Engine F keeps the result of `force` of a glued value or of a neutral application of a constant for the current declaration. A recursor application has no unfolding slot, so before this change each `force` of the same value did the iota steps again. On the Arena test `gf3-matrix-product`, engine F used 109.55 G instructions and now uses 67.57 G.
- The value arena of engine F has a limit of 2^18 nodes in each array, about 25 MiB. Before this change the limit was 2^22. When engine F fills the arena, engine R does the work again, so a smaller limit wastes less work. On the 42 Arena perf tests, engine F used 1537 G instructions in total and now uses 1326 G. Engine R alone uses 1142 G. On `grind-ring-5`, engine F used 121.19 G and now uses 27.89 G. 21 tests still use more than 6 G. Engine R alone uses more than 6 G on 19 of them and does not finish in 60 s on 1 of them (`magma-list-pair-n21`).
- `scripts/arena-build.py` builds the Arena tests with a `url` field, such as Mathlib. It fetches the pinned commit of the repository, runs the `pre-build` commands with bash, and exports the module with the `leanexport` binary of the toolchain of the repository. It reads the test files with PyYAML if it is installed. With `--check RULEAN`, it sends each export to `rulean check -` through a pipe and does not write the export to the disk. The con-leche test is accepted in this mode.
- Engine R checks axioms, definitions, theorems and opaque constants in the scratch tier of spec 04.8. The terms that the checker makes for one declaration go into a separate node array, and the checker clears that array after the declaration. Inductive and quotient declarations use the frozen tier. On the full Init prelude, the check now takes 54 s and 964 MB, and before this change it took 93 s and 3.45 GB. On Std, it now takes 60 s and 1.6 GB, and before this change it took 192 s and 4.55 GB.
- `rulean check` reads the export one line at a time, and computes the SHA-256 digest of the input at the same time. The input is not in memory as a whole, so the peak memory of a check is less by the size of the export. A check of standard input with `-` works the same way.
- `rulean check` without `--parse-only` checks the export with engine R. Before this change, it declined.
- The `arena parse` CI job is now the `arena` job. It also checks the verdicts of the Arena tests.

## [0.0.3] - 2026-11-22

### Added

- `rulean-nat` has the `Nat` type of spec 04.6 with the 15 kernel operations, `log2` and decimal conversion. Multiplication uses Karatsuba from 32 limbs, and division uses algorithm D of Knuth. The tests compare each operation with `num-bigint`.
- `rulean-store` has the term store of spec 04: `u32` handles with the kind in the handle, one node array for each kind, side records with the hash, the loose bound variable range and the flags, and hash-consing with an open-addressing table. It also interns strings, names, levels, level lists and natural number literals.
- `rulean-format` has the lean4export NDJSON 3.x parser of spec 07.1. It is a hand-written scanner that writes into the term store and returns the declaration stream of spec 04.7. It checks the input rules of 07.1.2: index tables with a defined bit, no duplicate keys or indices, strict integers, UTF-8 and surrogate pairs, `natVal` form and bound, and `mdata` stripping. All 225 Arena tests parse.
- `rulean-core` has the universe level functions of spec 05.6, as a transcription of `level.cpp` of the official kernel v4.35.0: `mk_max` and `mk_imax` with their simplifications, `normalize` with a cache for each level handle, `is_equivalent`, `is_geq`, `normalizes_to_zero`, `instantiate` and the name order of the kernel.
- `rulean-core` has the expression operations of engine R, as a transcription of `instantiate.cpp`, `abstract.cpp`, `expr.cpp` and `expr_eq_fn.cpp` of the official kernel v4.35.0: `instantiate`, `instantiate_rev`, `abstract_fvars`, `lift_loose_bvars`, `lower_loose_bvars`, `has_loose_bvar`, `instantiate_lparams`, the application spine functions, `head_beta`, `cheap_beta_reduce` and `expr_equal`. Each operation has a cache keyed by the node and the binder offset.
- `scripts/arena-fetch.sh` downloads the Arena tests and results and keeps only the tests whose export has the hash of the results.
- The `bench` workflow runs the official kernel of Lean v4.35.0 on the Arena tests each week and compares its instruction counts with the Arena numbers.
- `docs/bench/baseline.md` records the first baseline run. The verdicts match the Arena on all 225 tests. The cachegrind counts are not within 2% of the Arena counts, so the 2% limit applies only to `perf`.
- `rulean-core` has the environment and the type checker of engine R, as a transcription of `type_checker.cpp`, `inductive_reduce_rec` and `quot_reduce_rec` of the official kernel v4.35.0. The checker infers types in the infer-only mode and in the check mode, reduces terms to weak head normal form in the official order (beta, zeta, projections, recursors, quotients, the `Nat` extension and delta), and decides definitional equality with lazy delta reduction, eta, structure eta, proof irrelevance, unit-like types and the `Nat` and `String` literal extensions. An error is a sticky fault, and a depth bound stops deep recursion. The `Nat` operations check the size bound of 128 MiB.
- `rulean-core` has the declaration checks of spec 05.9 and 06.5, as a transcription of `environment.cpp` and `quot.cpp` of the official kernel v4.35.0: axioms, definitions, theorems, opaque constants, mutual blocks of unsafe or partial definitions and the quotient constants. An unsafe definition may refer to itself, and a safe declaration may not refer to an unsafe or partial constant. The first quotient declaration adds the four reference constants. Each exported quotient declaration must be equal to its reference constant. A rejected declaration does not change the environment.
- `rulean check --parse-only` parses an export into the term store and prints the counts, the store memory and the time. Without `--parse-only`, `check` still declines until M2. A parse reject exits with code 4, and a decline exits with code 2.
- `scripts/arena-parse.sh` runs `rulean check --parse-only` on every Arena test, and the new `arena parse` CI job runs it on the downloaded Arena.
- `rulean-core` has the inductive checks of spec 06.2, as a transcription of `add_inductive` in `inductive.cpp` of the official kernel v4.35.0: the type and constructor checks, the uniform parameter occurrences, strict positivity, the universe bound of the fields, the elimination level, the K flag and the recursor rules. The checker makes the recursors and compares the types, constructors and recursors of the export with its own declarations.
- `rulean-core` has the nested inductive types of spec 06.3, as a transcription of `elim_nested_inductive_fn` and `restore_nested` in `inductive.cpp` of the official kernel v4.35.0. The checker replaces each nested occurrence with an auxiliary type, checks the larger mutual block, and then restores the nested occurrences in the types, constructors and recursors. The export must have the auxiliary recursors with the names `I.rec_1`, `I.rec_2` and so on. All 225 Arena tests give the expected verdict, and the full Init prelude is accepted.
- `rulean-core` has the primitive pinning of spec 05.8. When the export declares a `Nat` operation, `Nat`, `String`, `String.ofList`, `Char`, `Char.ofNat`, `List` or `eagerReduce`, the checker compares the SHA-256 digest of the declaration with the digest of the reference declaration of the `v4.35` profile. If the digests are not equal, the extension of that name is off, and the constant unfolds like any other definition. This is deviation D1. `Checker::trust_primitives` keeps the extensions on, as the official kernel does. The `Checker::pin_mismatch` list gives the names that are not equal to their reference.
- `scripts/pin-digests.py` computes the reference digests from lean4export files. The `arena parse` CI job checks that the digests in `pin_ref_v4_35.in` are the digests of the Lean v4.36.0 exports of the Arena, and that engine R accepts the full Init prelude with no pin mismatch.
- `docs/deviations.json` is the deviation register of spec 05.12.

### Changed

- The store hash of a `lam`, `pi` or `let` node does not mix the binder name or the binder info. This is the method of Lean. Alpha-equivalent terms now have equal hashes, so `expr_equal` can use the hash to reject unequal terms.

### Fixed

- The `extract` job failed on `rulean-nat`, because Aeneas binds its `Fuel` type to the Lean name `Nat`. The type now has the Lean name `BigNat` in the extracted code. The Rust name does not change.
- `cargo xtask all` runs the subset check too. Before this change, the `policy` CI job did not check the Aeneas subset.
